# Internacionalización de Tabacalera Tamboril

Implementada el 7 de octubre de 2026 a partir de la auditoría y de la petición posterior de añadir chino. Hay cuatro catálogos completos: español, inglés, francés y chino simplificado. Las páginas activas, navegación, biblioteca, composición, guía, formularios, accesibilidad, controles, errores locales y metadatos utilizan traducciones.

## Idiomas y URLs

| Idioma | Código | Inicio | Ejemplo |
| --- | --- | --- | --- |
| Español | `es` | `/` | `/leaf-library` |
| Inglés | `en` | `/en` | `/en/leaf-library` |
| Francés | `fr` | `/fr` | `/fr/leaf-library` |
| Chino simplificado | `zh-CN` | `/zh-CN` | `/zh-CN/leaf-library` |

La URL determina el idioma incluso si existe otra preferencia en localStorage. Se guarda la elección en `tamboril-language`, pero no se redirigen enlaces explícitos según esa preferencia. `/es/...` redirige a la URL española sin prefijo conservando parámetros y ancla. Un prefijo no soportado, como `/de`, no se interpreta como idioma: muestra 404.

El selector aparece en la navegación, tiene un acceso flotante cuando esta está oculta y también está disponible dentro de los modales. Cambiar idioma conserva la vista montada, formularios, filtros, hojas seleccionadas, paso de composición y modales abiertos. Los parámetros y anclas se mantienen. Los nombres de variedades y los identificadores técnicos siguen siendo estables.

## Arquitectura y archivos

- `src/i18n/config.js`: códigos, nombres nativos, prefijos, locales para `Intl` y locales Open Graph.
- `src/i18n/index.js`: inicialización de i18next antes de montar React, fallback español e interpolación segura mediante React.
- `src/i18n/resources.js`: recursos JSON importados explícitamente para navegador y build. No requiere peticiones de traducciones en tiempo de ejecución.
- `src/i18n/locales/{es,en,fr,zh-CN}/`: nueve namespaces por idioma: `common`, `navigation`, `pages`, `leaves`, `craft`, `guide`, `controls`, `errors`, `seo`. Cada idioma contiene 764 claves.
- `src/i18n/routing.js`: separar idioma y ruta base; localizar enlaces internos conservando query/hash. Excluye assets, URLs externas y enlaces que solo contienen ancla o query.
- `src/i18n/navigation.js`: importar de aquí `Link`, `Navigate`, `useNavigate`, `useLocation` y `useSearchParams` en vistas localizadas. Los destinos absolutos internos incorporan el idioma actual.
- `src/i18n/locationContext.js` y `navigationHooks.js`: conservan la ubicación real, incluida la parte del idioma. `App` proporciona ese contexto y entrega la ruta base a `Routes`. Así se reutilizan las mismas rutas y componentes sin remontarlos al cambiar idioma. `useLocation` del adaptador devuelve la ruta base; `useLocaleLocation` devuelve la URL real.
- `src/components/LanguageSwitcher.jsx` y `src/styles/language-switcher.css`: selector accesible y adaptación visual, incluidas fuentes de respaldo CJK.
- `src/i18n/useLocalizedLeaves.js`, `localizeLeaf.js` y `src/data/leafPresentation.js`: descripciones de las 21 hojas, categorías, orígenes y capítulos traducidos sin mutar el inventario.
- `src/i18n/messages.js`: mensajes almacenados como `{ key, values, detail }`, resueltos al mostrarlos. Los detalles de servidor se conservan; no se traducen diagnósticos arbitrarios.
- `src/i18n/translate.js`: traducción pura sin React ni navegador para SEO y pruebas.

Las claves son planas y pueden contener puntos; `keySeparator: false` es deliberado. Ejemplo: `t('seo:home.title')`. Las frases con variables se traducen completas; no concatenar fragmentos cuya posición dependa del idioma. Para plurales usar `count` y las formas de i18next; chino utiliza la categoría `other`. Para texto editorial con énfasis o saltos usar `Trans` con componentes nombrados, conservando las etiquetas de los catálogos.

No guardar el resultado de `t()` en Zustand ni calcular etiquetas traducidas al importar un módulo. `routesConfig` y el estado del encabezado guardan claves; los arrays editoriales se resuelven durante el render. Los filtros guardan el origen original y la categoría estable; su etiqueta y orden se calculan con el idioma actual. Las preferencias de layout se indexan por ruta base, compartidas entre idiomas.

La autenticación sigue siendo local y los formularios siguen mostrando resultados locales. El inventario, límites de composición, IDs de perfiles, rutas de recursos y valores funcionales no cambian. Los archivos de páginas antiguas sin ruta, como `Service` y `BlendGuide`, no forman parte de la cobertura editorial activa ni se han habilitado.

## SEO y salida del build

`src/config/seoConfig.js` comparte traducciones con el navegador. `src/components/Seo.jsx` actualiza metadatos durante la navegación y `plugins/seoPlugin.js` genera 36 shells HTML, correspondientes a nueve rutas por cuatro idiomas. Cada ruta tiene título, descripción, canonical propio, cinco alternates (cuatro idiomas más `x-default` español), idioma del documento, Open Graph y JSON-LD localizados.

Se generan cuatro manifests (`site.es.webmanifest`, etc.), cuatro archivos 404 y un sitemap con 24 URLs: inicio, biblioteca, historia, menú, contacto y experiencia sensorial en cuatro idiomas. Reserva, login y composición conservan `noindex`. Query y hash no forman parte de canonical ni del sitemap. La configuración de indexación previa del código se mantiene.

Los shells contienen metadatos iniciales; el cuerpo de la aplicación sigue siendo una SPA que necesita JavaScript. La comprobación local no valida respuestas HTTP ni reglas de Vercel. Tras desplegar hay que verificar entradas directas, recargas y HTTP 404 real. En rutas desconocidas localizadas, la aplicación cambia el idioma del 404 al ejecutar JavaScript; el alojamiento puede entregar inicialmente el 404 español global.

## Añadir o mantener traducciones

1. Editar la misma clave en los cuatro JSON del namespace correspondiente. No usar texto visible como identificador del estado.
2. Conservar placeholders como `{{count}}`, `{{name}}` y etiquetas de `Trans`. Traducir frases completas y revisar el vocabulario de capa, capote y tripa con criterio editorial.
3. Para añadir un idioma, declararlo en `config.js`, crear sus nueve catálogos y añadir sus imports y recursos a `resources.js`. Definir su prefijo, locale de `Intl` y locale Open Graph. Los menús, rutas SEO y manifests recorren esa configuración.
4. Añadir casos de navegador y revisar anchura, tipografía, plurales, formularios, modales y errores. Si se añade un idioma RTL, adaptar estilos y dirección del documento: la implementación actual cubre cuatro idiomas LTR.
5. Ejecutar las comprobaciones siguientes antes de aceptar cambios.

## Validación

```sh
npm run check:i18n
npm test
npm run build
npm run check:i18n:build
npx playwright install chromium   # solo al preparar el entorno
npm run test:e2e
```

El comprobador de catálogos verifica claves, valores, placeholders, etiquetas de `Trans` y referencias estáticas. Las 19 pruebas unitarias incluyen rutas, plurales, inventario inmutable, SEO y errores reactivos. Las nueve pruebas de Chromium recorren las 36 entradas y comprueban formularios, filtros, capítulos, composición, login protegido, query/hash, guía, controles, historial, 404, navbar oculta y anchura móvil francesa/china. El comprobador de build valida los archivos HTML, manifests y sitemap generados.

El build conserva el aviso de tamaño de bundle: los catálogos se incluyen juntos para disponer de traducciones y SEO consistentes desde la primera carga. El lint general del repositorio tenía errores antes de esta implementación, especialmente en librerías heredadas y la configuración de JSX; debe distinguirse de los cambios de i18n. Las fechas nativas de los formularios pueden adoptar el formato del navegador/sistema. Nombres propios, código, stacks y detalles técnicos externos no se traducen. Las traducciones requieren revisión editorial humana antes de publicación.
